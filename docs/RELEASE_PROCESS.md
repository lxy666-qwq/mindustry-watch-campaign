# 迭代与发布流程

每轮保留可回看的代码与可运行程序。版本号采用`主版本.次版本.修订版本`：新增关卡或机制升次版本，小范围修复升修订版本。

1. 记录目标与验收条件，保留用户既有文件和无关修改。
2. 在工作分支开发，更新`core/assets/watch-version.txt`和中英文文案。
3. 更新README、CHANGELOG、关卡说明与本版本验证记录，只写已完成的功能和实测结果。
4. 运行针对改动的测试与必要回归，编译桌面包，检查真实游戏的加载、提示和关键变化。
5. 检查暂存差异，不提交密码、凭据、缓存、个人存档、JDK和Gradle二进制。课程Word与学号资料留在本地课程目录。
6. 提交源码并建立不可覆盖的`coursework-vX.Y.Z`标签。发现问题时修复并发布新版本，不重写历史标签。
7. 在`D:\软件工程\版本归档\vX.Y.Z`保存程序、源码ZIP、启动脚本、许可证、README、更新日志和验证记录。Arc源码按匹配版本另行归档。
8. GitHub已登录时，推送分支和标签，在Releases发布程序及源码，上传后读取远端确认实际状态。未登录或失败时标记本地完成、远端未完成。

维护自动测试、桌面运行、人工完整试玩三类证据，某一类通过不能替代其他类别。记录待改进问题及复现条件。

遵循用户要求，不执行哈希、校验和或摘要指纹校验。
